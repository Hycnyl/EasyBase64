# 文件访问与恢复实现说明

EasyBase64 的文件转换经 `ContentResolver` 和 Android Storage Access Framework 完成。源文档与结果文档不依赖普通文件路径；应用不申请全盘访问权限。

## 保存方式

- 每批在所选输出目录中新建 `EasyBase64-时间-批次标识` 子目录。
- 编码追加 `.b64`；解码移除最后的 `.b64`（不区分大小写），否则追加 `.decoded`。
- 所有文件先创建独立 `.partial` 文档。完整格式校验、物理 EOF、输出 flush 和双方 close 成功后，才进入提交。
- 支持重命名的提供方优先重命名；成功返回的新 URI 接替暂存 URI 的所有权，应用不会再查询或删除可能已经被提供方撤销的旧 URI。不支持重命名时创建新目标并流式复制，复制关闭成功后删除暂存文档。
- 任何失败、取消都会尝试删除本次新建的未完成结果。删除失败的 URI 保留在尝试记录里，用户可再次清理；此前已成功的结果不参与失败清理。
- 文件夹扫描保留相对目录层级。已创建的目录 URI 记入数据库，重试会复用本批自己的目录。

## 持久化与中断

Room 分别存储批次头、逐文件元数据、逐次尝试和输出目录关系；没有将整个批次写进单个数据库行，以免大量文件触发 Android CursorWindow 单行大小限制。数据库不存储文件正文。

应用启动只恢复元数据，不自动重启转换。遗留的 Running / Committing 项以及正在运行批次中的未开始项标为 Interrupted。可访问的暂存和未验证最终 URI 会列为待清理位置。失败、中断、取消后的重试保留旧尝试，并使用最初冻结的编解码参数。

SAF 不保证原子重命名。在重命名发生但新 URI 尚未记入数据库的极短窗口内进程被终止，无法凭空恢复提供方生成的新 URI。尝试详情保留拟用名称和父目录 URI，并提示人工检查。应用不会猜测某个同名文件属于本次尝试并擅自删除。

如果仍有待清理 URI 或无法验证的重命名记录，新建批次不会静默覆盖这些记录。用户可以先清理，或明确清除记录后继续；清除记录只删除元数据，不删除源文件、成功结果或残留文件。

## 提供方关系与权限

同一提供方的输入/输出目录使用 `DocumentsContract.isChildDocument` 判断关系。输入树中输出目录及其后代不会加入队列。仅 Android 本地 ExternalStorageProvider 在不支持关系查询时使用其路径型 document ID 作为已知回退；对于任意提供方，不根据 URI 字符串猜测层级，关系未知时拒绝扫描并提示换输出位置或改用多选。

持久化授权由 Activity 使用系统选择器实际返回的 flags 获取，仓库只检查授权是否持久保存。授权失效、云盘断连和输入不可用分别显示错误；不能仅凭 IOException 判断磁盘已满。应用自身没有 INTERNET 权限，但用户选择的云盘提供方可能联网。

用户取消会设置取消标志并尝试关闭活动流、取消目录查询。不同提供方对关闭请求的响应时间不同，所以界面会显示“正在取消”，直至执行器完成清理。系统服务停止/超时使用 Interrupted 状态，不承诺永久后台运行。
